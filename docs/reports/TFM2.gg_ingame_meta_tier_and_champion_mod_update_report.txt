TFM2.gg 인게임 메타 티어 애드온 / 챔피언 추가 모드 대응 업데이트 상세 리포트
작성일: 2026-06-05
대상 버전: Teamfight Manager 2 0.4.10 대응 TFM2.gg

===============================================================================
0. 이 문서의 초점
===============================================================================

이 문서는 TFM2.gg의 전체 메타 스코어 산식 설명이 아니라, 아래 두 가지 업데이트에만
초점을 맞춘다.

1. 인게임 메타 티어 자동 설정 애드온

   - 대시보드에서 계산한 메타 티어를 게임 안의 챔피언 티어 분류표에 반영하는 기능
   - OP/1/2/3/4/-를 게임 내부 S/A/B/C/D/No-Tier로 변환하는 기능
   - 대시보드와 인게임 티어표 불일치를 줄이기 위한 정책 TSV 구조 개선
   - 피어리스/하드 피어리스 룰 설정과 애드온 정책 동기화
   - 적용 여부 확인용 로그 및 최신 적용 스냅샷 출력

2. 챔피언 추가 모드 대응

   - Steam 창작마당 챔피언 추가 모드 감지
   - 설치 도구에서 챔피언 추가 모드 활성/비활성 관리
   - 활성화된 창작마당 챔피언을 대시보드 챔피언 목록에 자동 병합
   - 모드 챔피언의 이름, 설명, 능력치, 스킬, 역할 추정, 스프라이트 표시
   - 모드 챔피언도 통계가 쌓이면 대시보드/애드온 정책 대상에 포함되는 구조

핵심 결론은 다음과 같다.

TFM2.gg는 이제 단순히 대시보드 안에서만 메타 티어를 보여주는 도구가 아니라,
대시보드에서 생성한 메타 티어 정책을 인게임 팀별 챔피언 티어표에 반영하고,
사용자가 구독한 챔피언 추가 모드까지 대시보드 분석 대상에 포함할 수 있는 구조로 확장되었다.

2. 인게임 메타 티어 애드온 업데이트 요약
===============================================================================

이번 업데이트에서 인게임 메타 티어 애드온은 다음 문제를 해결하는 방향으로 개선되었다.

2.1. 기존 문제: 대시보드와 인게임 티어표가 완전히 일치하지 않음

사용자 피드백:

   대시보드에서는 OP, 1티어, 2티어가 보이는데
   인게임 게임 정보 티어 분류표에서는 C, D 위주로 보인다.

원인:

   대시보드의 메타 스코어는 0~100 스케일이지만, 실제 값은 매우 보수적으로 압축되어 있다.
   일반적인 세이브에서는 65점을 넘는 챔피언이 많지 않다.

   그런데 기존 방식처럼 champion_tier_policy.tsv의 overall 컬럼에 raw 메타 스코어를 그대로 넣으면,
   네이티브 애드온 또는 게임 내부 해석 기준에서 다음 컷으로 다시 티어를 계산할 수 있었다.

      S: overall >= 85
      A: overall >= 72
      B: overall >= 60
      C: overall >= 48
      D: overall < 48

   이러면 대시보드에서는 1티어인데 raw metaScore가 55점대인 챔피언이
   인게임에서는 C티어로 보이는 문제가 생긴다.

해결:

   인게임 티어 표시용 overall을 raw 메타 스코어가 아니라
   S/A/B/C/D 표시를 안정적으로 유지하기 위한 앵커값으로 분리했다.

2.2. 현재 매핑 기준

대시보드 메타 티어와 인게임 티어는 다음처럼 매핑된다.

   대시보드 OP  -> 인게임 S
   대시보드 1   -> 인게임 A
   대시보드 2   -> 인게임 B
   대시보드 3   -> 인게임 C
   대시보드 4   -> 인게임 D
   대시보드 -   -> 인게임 No-Tier

중요한 점:

   이 매핑은 raw 메타 스코어 점수 컷이 아니라,
   대시보드가 최종 계산한 "메타 티어"를 기준으로 한다.

즉 대시보드가 OP라고 판단한 챔피언은 인게임 S로 들어가고,
대시보드가 1티어라고 판단한 챔피언은 인게임 A로 들어간다.

2.3. overall 앵커값

인게임 메타 티어 정책 파일에서는 다음 앵커값을 사용한다.

   S = 90.0
   A = 75.0
   B = 62.0
   C = 50.0
   D = 35.0
   No = overall 비움

예시:

   hunter              S    90.0
   ghost               A    75.0
   guardian_spirit     B    62.0
   soldier             C    50.0
   knight              D    35.0
   hammerer            No

이렇게 한 이유:

   인게임 표시용 티어와 대시보드 raw 메타 스코어를 분리하기 위해서다.
   raw 메타 스코어는 분석용 점수이고, 인게임 티어표는 게임 내부 S/A/B/C/D/No-Tier 체계에 맞춰야 한다.

2.4. No-Tier 처리

대시보드에서 "-"인 챔피언은 인게임에서 No-Tier로 들어간다.

네이티브 애드온은 다음 label을 No-Tier로 인식한다.

   NO
   NO-TIER
   NONE
   -

현재 정책 생성기는 대시보드 "-"를 No로 내보내고,
No 행은 overall을 비워 둔다.

이 방식의 장점:

   저표본 챔피언이나 통계가 없는 챔피언을 억지로 C/D에 넣지 않는다.
   게임 내부의 NoTier 상태로 명확히 둘 수 있다.

3. 인게임 메타 티어 정책 생성 기준
===============================================================================

3.1. 정책 기준 범위

인게임 메타 티어 자동 분류 정책은 기본적으로 최신 패치 전세계 대회 통계를 기준으로 생성된다.

현재 기준:

   scope  = tournament
   patch  = latest
   region = all
   role   = all

즉 "솔랭 포함 전체 통계"가 아니라,
"최신 패치 전세계 대회 통계"를 기준으로 인게임 티어표를 만든다.

이렇게 한 이유:

   인게임 티어표는 게임 내부 팀/AI가 참고하는 챔피언 평가표 성격이 강하다.
   솔랭은 밴 데이터가 없고 대회 밴픽과 성격이 다르기 때문에,
   인게임 티어표 기준으로는 전세계 대회 통계가 더 보수적이고 명확하다.

3.2. 대시보드 분석 화면과 인게임 정책의 차이

대시보드 화면:

   사용자가 자유롭게 전체/대회/솔랭/지역/역할/패치 필터를 바꿔 분석할 수 있다.

인게임 메타 티어 정책:

   최신 패치 전세계 대회 기준으로 생성된다.

정리하면:

   대시보드는 분석용이다.
   인게임 티어 정책은 게임에 적용되는 보수 기준이다.

3.3. 정책 TSV 헤더에 남는 정보

champion_tier_policy.tsv에는 정책이 어떤 기준으로 만들어졌는지 헤더로 남긴다.

예시:

   Source: tournament patch 2026.1.0
   Patch: 2026.1.0
   Scope: tournament
   Region: all
   Role: all
   Model: tfm2gg-meta-v1
   Preset: classic
   PolicyPresetSource: dashboard setting
   Sample: normal min=10
   PolicyKind: championTier
   OverallSemantic: dashboard_meta_tier_for_in_game_sabcd_no

이 헤더 덕분에 사용자는 정책 파일만 열어도 다음을 확인할 수 있다.

   어떤 세이브 기준인지
   어떤 패치 기준인지
   대회/솔랭 중 무엇을 기준으로 했는지
   어떤 룰 프리셋으로 계산했는지
   최소 표본 기준이 무엇인지
   S/A/B/C/D/No 변환 방식이 무엇인지

4. 피어리스/하드 피어리스 룰과 애드온 동기화
===============================================================================

4.1. 기존 문제

기존에는 대시보드에서 피어리스나 하드 피어리스로 화면을 보고 있어도,
애드온 정책 생성은 classic 기준으로 고정되는 문제가 있었다.

피어리스 유저 입장에서는 이게 꽤 중요하다.

classic:

   승률 중심 판단

fearless/hardFearless:

   밴픽 압력의 의미가 더 커짐

하드 피어리스에서는 좋은 챔피언이 한 번 쓰인 뒤 다시 못 나오거나,
상대에게 주기 싫어서 밴으로 묶이는 경우가 많다.
따라서 classic 기준 티어표를 인게임에 넣으면 실제 플레이 감각과 어긋날 수 있다.

4.2. 현재 개선 방식

정책 프리셋은 다음 순서로 결정된다.

1. 환경변수 TFM2_POLICY_PRESET

   개발/검증용으로 강제 프리셋을 줄 수 있다.

2. 대시보드 설정 파일 policy-settings.json

   대시보드에서 선택한 정책 프리셋 또는 "화면 룰 따라가기" 설정을 반영한다.

3. fallback

   설정이 없거나 잘못되면 classic으로 돌아간다.

4.3. 지원 모드

지원되는 정책 프리셋:

   classic
   fearless
   hardFearless

지원되는 동기화 방식:

   인게임 애드온: 화면 룰 따라가기
   인게임 애드온: classic 고정
   인게임 애드온: fearless 고정
   인게임 애드온: hardFearless 고정

4.4. 정책만 빠르게 재생성

대시보드에는 전체 세이브 재분석 없이 애드온 정책 TSV만 다시 생성하는 policy-only 흐름이 있다.

목적:

   룰 프리셋을 바꿀 때마다 전체 save probe와 통계 재생성을 다시 돌리지 않아도 된다.
   이미 만들어진 meta-data.js의 통계를 기준으로 champion_tier_policy.tsv와 ai_champion_policy.tsv만 갱신할 수 있다.

이 흐름 덕분에 피어리스/하드 피어리스 기준을 바꾸는 작업이 훨씬 가벼워졌다.

===============================================================================
5. 네이티브 애드온 적용 방식
===============================================================================

5.1. 적용 타이밍

tfm2_meta_champion_tiers 네이티브 모드는 InGame scene에서 post_update 시점에 작동한다.

동작 흐름:

1. 게임이 InGame scene인지 확인한다.
2. champion_tier_policy.tsv를 찾는다.
3. 파일 수정 시간과 크기를 보고 캐시가 유효한지 확인한다.
4. 정책 파일이 바뀌었으면 다시 읽는다.
5. 모든 팀의 champion_tiers 맵에 정책을 적용한다.
6. 변경이 있었으면 debug.log와 tier-policy-latest.txt를 기록한다.

5.2. 적용 대상

적용 대상은 게임 DB 안의 모든 팀이다.

팀마다 다음 필드에 반영된다.

   Team.champion_tiers

각 챔피언 ID에 대해:

   Some(S/A/B/C/D/NoTier)이면 team.champion_tiers에 삽입 또는 갱신

현재 구현은 No-Tier도 명시적으로 ChampionTier::NoTier로 넣을 수 있다.

5.3. 정책 파일 탐색 순서

애드온은 config.ini가 있으면 우선 그 경로를 사용한다.

지원 설정:

   policy_path=C:\Path\To\champion_tier_policy.tsv
   policy_dir=C:\Path\To\policy_exports
   policy_file=champion_tier_policy.tsv

config.ini가 없거나 경로가 비어 있으면 다음 fallback을 본다.

1. 게임 폴더\TFM2.gg\resources\app\tfm2_meta_dashboard\data\policy_exports
2. 게임 폴더\TFM2_Meta_Dashboard\resources\app\tfm2_meta_dashboard\data\policy_exports
3. 모드 폴더\champion_tier_policy.tsv

설치 도구는 설치 시 config.ini를 다시 써서 대시보드의 policy_exports 폴더를 가리키게 한다.
이렇게 해서 대시보드가 만든 최신 정책과 인게임 애드온이 같은 파일을 보도록 맞춘다.

5.4. 적용 확인 방법

사용자가 작동 여부를 확인할 때 가장 중요한 파일은 두 개다.

1. debug.log

   정책 로드, 파싱 실패, 적용 요약이 기록된다.

2. tier-policy-latest.txt

   마지막으로 적용된 정책 스냅샷이다.
   챔피언 ID와 적용 티어가 줄 단위로 기록된다.

예:

   source=client_post_update policy_file=... teams=... policy_rows=... changed=...
   source=C:\...\champion_tier_policy.tsv
   hunter    S
   ghost     A
   hammerer  No

이 파일이 갱신되어 있으면 애드온이 정책을 읽고 실제 적용 루프까지 들어갔다는 강한 근거가 된다.

===============================================================================
6. 인게임 메타 티어 업데이트로 해결한 사용자 피드백
===============================================================================

6.1. "인게임에는 C/D만 보여요"

원인:

   raw 메타 스코어를 overall에 그대로 넣으면,
   게임 내부 또는 DLL의 overall 컷 기준 때문에 대부분 C/D로 내려갈 수 있었다.

해결:

   대시보드 메타 티어를 S/A/B/C/D/No 앵커값으로 변환한다.

결과:

   대시보드 OP -> 인게임 S
   대시보드 1 -> 인게임 A
   대시보드 2 -> 인게임 B
   대시보드 3 -> 인게임 C
   대시보드 4 -> 인게임 D
   대시보드 - -> 인게임 No-Tier

6.2. "대시보드 티어표랑 인게임 티어표가 완전히 일치하지 않아요"

원인 후보:

1. 게임이 아직 재시작되지 않음
2. 정책 TSV가 최신 대시보드 기준으로 재생성되지 않음
3. 대시보드 화면은 특정 필터/룰을 보고 있는데, 인게임 정책은 최신 패치 전세계 대회 기준임
4. policy preset이 classic/fearless/hardFearless 중 다른 값으로 생성됨
5. 애드온이 fallback 경로의 오래된 champion_tier_policy.tsv를 읽음

개선:

   정책 파일 헤더에 Scope/Patch/Preset/PolicyPresetSource를 명확히 기록한다.
   설치 도구가 policy 파일 존재 여부와 정책 요약을 상태 화면에 표시한다.
   애드온이 tier-policy-latest.txt를 남겨 실제 읽은 정책을 확인할 수 있게 한다.

주의:

   대시보드에서 "전체 + 솔랭 + 특정 지역 + 특정 역할" 같은 화면을 보고 있다면,
   그 화면의 메타 티어와 인게임 정책 티어가 완전히 같지 않을 수 있다.

   인게임 정책은 기본적으로 최신 패치 전세계 대회 기준이다.

6.3. "피어리스 기준으로도 인게임 티어를 넣고 싶어요"

해결:

   대시보드 정책 설정에서 인게임 애드온 정책을 화면 룰과 동기화하거나,
   fearless/hardFearless로 고정할 수 있게 했다.

효과:

   피어리스 유저는 classic 기준이 아닌 피어리스/하드 피어리스 메타 티어를 인게임에 넣을 수 있다.

===============================================================================
7. 챔피언 추가 모드 대응 업데이트 요약
===============================================================================

이번 업데이트의 두 번째 큰 축은 챔피언 추가 모드 대응이다.

목표:

   사용자가 Steam 창작마당에서 챔피언 추가 모드를 구독했을 때,
   TFM2.gg 설치 도구와 대시보드가 그 모드를 인식하고,
   활성화된 모드의 챔피언을 대시보드에 표시할 수 있게 만드는 것.

중요한 설계 방향:

   챔피언 개별 온오프는 하지 않는다.
   창작마당 모드 단위로 켜고 끈다.

이유:

   Teamfight Manager 2의 모드 시스템은 기본적으로 모드 단위 활성/비활성 구조다.
   모드 내부 챔피언을 개별로 뜯어서 켜고 끄면,
   해당 모드의 밸런스, 번역, 스프라이트, 스킬 참조, override 구조가 깨질 수 있다.

따라서 TFM2.gg의 v1 구현은 안정성을 우선해 "모드 단위 관리"로 잡았다.

===============================================================================
8. 설치 도구의 챔피언 추가 모드 매니저
===============================================================================

8.1. 감지 방식

설치 도구는 Steam 창작마당 content 폴더를 찾는다.

기본 구조:

   Steam\steamapps\workshop\content\3009300\{workshop_item_id}

각 workshop item 안에서 다음을 찾는다.

   mod.mod_info

mod.mod_info가 바로 item 폴더에 있거나,
하위 폴더에 들어 있는 경우도 처리한다.

8.2. 챔피언 추가 모드 판정 기준

설치 도구는 모드 루트 안에 다음 폴더와 파일이 있는지 확인한다.

   champion\*.data_champion

이 파일이 하나 이상 있으면 챔피언 추가 모드로 간주한다.

각 .data_champion 파일에서 챔피언 ID를 읽는다.
id 필드가 없으면 파일명을 fallback으로 사용한다.

8.3. 설치 도구에서 표시하는 정보

챔피언 추가 모드 매니저는 다음 정보를 표로 보여준다.

   상태
   모드 이름
   mod_id
   버전
   챔피언 수
   Workshop ID
   주의 사항

주의 사항 예:

   champion_view style override 포함
   DLL 포함

style override가 있다는 것은 게임 UI 일부를 덮어쓸 수 있다는 뜻이다.
DLL 포함은 코드 모드일 수 있다는 뜻이다.
둘 다 반드시 나쁜 것은 아니지만, 사용자에게 위험 신호를 보여주는 편이 안전하다.

8.4. 활성/비활성 처리

설치 도구는 다음 파일을 수정한다.

   Teamfight Manager2\config\game\mods.json

활성화할 때:

   enabled_mods에 mod_id 추가
   known_workshop_mods에 mod_id 추가

비활성화할 때:

   enabled_mods에서 mod_id 제거
   known_workshop_mods에는 유지

작업 전에는 mods.json을 백업한다.

8.5. 게임 실행 중 변경 차단

설치 도구는 TeamfightManager2.exe가 실행 중이면 챔피언 모드 활성/비활성 변경을 막는다.

이유:

   게임이 실행 중인 상태에서 mods.json을 바꾸면,
   현재 세션의 로드 상태와 파일 상태가 어긋날 수 있다.
   특히 챔피언 추가 모드는 저장 데이터와 게임 DB에 영향을 줄 수 있으므로,
   게임 종료 후 바꾸는 것이 안전하다.

8.6. 적용 시점

게임:

   챔피언 추가 모드 활성/비활성은 게임 재시작 후 적용된다.

대시보드:

   대시보드는 통계 데이터 재생성 또는 새로고침 시 현재 enabled_mods를 읽어 활성 모드의 챔피언을 가져온다.
   이미 떠 있는 대시보드가 오래된 meta-data.js를 보고 있다면, 새로고침 또는 통계 재생성이 필요하다.

즉 설치 도구에서 모드를 켠 직후, 게임은 반드시 재시작해야 하고,
대시보드도 최신 데이터로 다시 생성되어야 가장 정확하다.

===============================================================================
9. 대시보드의 외부 챔피언 로딩 방식
===============================================================================

9.1. 활성 모드만 로딩

대시보드 데이터 생성기는 게임 설치 폴더를 찾은 뒤,
다음 파일에서 활성화된 모드 ID 목록을 읽는다.

   Teamfight Manager2\config\game\mods.json

그 뒤 창작마당 폴더에서 감지된 챔피언 추가 모드 중,
enabled_mods에 들어 있는 모드만 로딩한다.

즉 구독만 되어 있고 비활성화된 모드는 대시보드 챔피언 목록에 넣지 않는다.

9.2. 중복 ID 방지

대시보드는 기존 기본 챔피언 ID 목록을 먼저 만든다.
외부 챔피언을 추가할 때 이미 같은 ID가 있으면 건너뛴다.

이유:

   기본 챔피언과 같은 ID를 가진 모드 챔피언이 들어오면
   통계, 이미지, 스킬, 정책 TSV가 충돌할 수 있다.

9.3. 외부 챔피언 payload 구성

외부 챔피언은 .data_champion 파일을 읽어 다음 payload로 변환된다.

   id
   name
   category
   tags
   rawTags
   description
   stats
   growth
   skills
   metrics
   roleFit
   bestRole
   asset
   overall
   tier
   modSource

modSource에는 다음 정보가 들어간다.

   type = workshop
   workshopId
   modId
   modName
   version

이 정보 덕분에 대시보드에서 특정 챔피언이 기본 챔피언인지,
어떤 창작마당 모드에서 온 챔피언인지 추적할 수 있다.

9.4. 이름과 설명 번역

대시보드는 모드 루트의 다음 파일을 읽는다.

   text\champion.i18n

언어 우선순위:

   ko
   en
   ja
   zh-CN

해당 언어의 description 섹션에서 챔피언 이름과 스킬 설명을 가져온다.
번역이 없으면 champion id 또는 data_champion 안의 description을 fallback으로 사용한다.

9.5. 능력치 로딩

외부 챔피언의 stat/growth는 다음 값으로 매핑된다.

   attack
   magicPower
   hp
   defence
   magicResistance
   moveSpeed
   moveSpeedDisplay

moveSpeedDisplay는 게임 내부 move_speed 값을 사람이 보기 쉬운 값으로 변환한다.

9.6. 역할 추정

외부 챔피언은 기본 챔피언처럼 충분한 사전 roleFit 정보가 없을 수 있다.
그래서 category와 tags를 보고 역할 적합도를 추정한다.

예:

   range 계열:
      bot 적합도 상승
      mid 보조 적합도

   magician/AP/magic 계열:
      mid 적합도 상승
      support 보조 적합도

   tank/melee 계열:
      top 적합도 상승
      jungle 보조 적합도

   heal/shield 계열:
      support 적합도 상승

이 추정은 완벽한 포지션 판정이 아니라,
대시보드 필터와 기본 표시를 위한 fallback이다.
실제 리플레이/세이브 통계가 쌓이면 byPosition 통계가 더 중요한 근거가 된다.

===============================================================================
10. 모드 챔피언 이미지/모델링 표시 개선
===============================================================================

10.1. 기존 문제

챔피언 추가 모드를 대시보드에 넣어도,
대시보드 목록에서 모드 챔피언 이미지가 공백으로 보일 수 있었다.

원인:

   기본 챔피언은 대시보드가 미리 가지고 있는 sprite atlas를 쓸 수 있지만,
   창작마당 챔피언은 각 모드 폴더 안의 별도 sprite sheet와 animation 파일을 읽어야 한다.

10.2. 현재 방식

대시보드는 외부 챔피언의 sprite 경로를 읽고,
모드 폴더 안에서 다음 파일을 찾는다.

   {sprite_path}#sheet.png
   {sprite_path}#anim.fanim

sprite 경로는 다음 형태를 유연하게 처리한다.

   asset/...
   {mod_id}/...
   상대 경로
   #sheet.png가 붙은 경로

10.3. idle frame 추출

대시보드는 #anim.fanim에서 우선 다음 animation tag를 찾는다.

   idle
   stand
   run
   attack
   skill
   skill2
   ult
   dead

해당 animation의 첫 frame에서 x, y, w, h 정보를 읽고,
sprite sheet에서 그 부분만 잘라 보여준다.

idle이 없으면 다른 animation의 첫 frame을 fallback으로 사용한다.

10.4. Base64 embedding

외부 sprite sheet는 파일 경로를 그대로 참조하지 않고,
5MB 이하인 경우 data:image/png;base64 형태로 meta-data.js에 삽입한다.

장점:

   대시보드가 모드 폴더의 상대 경로 문제에 덜 흔들린다.
   설치 경로가 달라도 meta-data.js 안에 이미지가 들어 있으므로 표시 안정성이 높다.

주의:

   sprite sheet가 5MB를 넘으면 삽입하지 않는다.
   이 경우 이미지가 비어 보일 수 있다.

10.5. 렌더링 스케일

외부 챔피언은 기본 챔피언과 sprite 크기가 다를 수 있다.
그래서 renderScale을 별도로 둔다.

   frame 높이 >= 72이면 renderScale = 1.45
   그 외 renderScale = 1.2

대시보드 app.js에서는 asset.external 여부를 보고 이 renderScale을 적용한다.

효과:

   모드 챔피언이 너무 작거나 크게 보이는 문제를 줄인다.
   목록/표/상세 화면에서 기본 챔피언과 비슷한 시각 크기로 보이도록 맞춘다.

===============================================================================
11. 챔피언 추가 모드와 메타 티어 애드온의 연결
===============================================================================

11.1. 모드 챔피언도 정책 TSV 대상에 포함 가능

대시보드 데이터 생성 시 활성 모드의 챔피언은 champions 배열에 추가된다.
그 뒤 정책 TSV 생성은 champions 배열 전체를 대상으로 돈다.

따라서 모드 챔피언도 다음 조건을 만족하면 champion_tier_policy.tsv에 들어갈 수 있다.

1. 설치 도구 또는 게임 설정에서 해당 창작마당 모드가 활성화되어 있음
2. 대시보드 데이터 생성기가 해당 모드의 .data_champion을 읽음
3. 챔피언 ID가 기본 챔피언과 충돌하지 않음
4. 해당 챔피언의 통계가 세이브/리플레이/메타 익스포트에 잡힘

11.2. 통계가 없는 모드 챔피언 처리

새로 추가한 모드 챔피언은 처음에는 통계가 없을 수 있다.

이 경우:

   대시보드 메타 티어 = "-"
   인게임 메타 티어 정책 = No
   AI 밴픽 정책 = 중립 C/50에 가까운 값

이것은 정상 동작이다.

통계가 없는 챔피언을 억지로 높은 티어에 넣으면,
게임 밸런스와 대시보드 신뢰도가 오히려 망가진다.

11.3. 통계가 쌓인 뒤

모드 챔피언이 실제 게임/세이브/리플레이에 등장하고,
pickCount와 winRate가 생기면 기존 챔피언과 같은 산식으로 평가된다.

즉 모드 챔피언도 결국 같은 메타 모델의 대상이 된다.

반영되는 항목:

   승률
   픽률
   밴률
   밴픽률
   역할 통계
   지역/대회/솔랭 범위
   메타 스코어
   메타 티어
   꿀챔 점수
   인게임 티어 정책

단, 실제로 어떤 항목까지 잡히는지는 게임 세이브와 export 구조가 해당 모드 챔피언을 어떻게 기록하느냐에 달려 있다.

===============================================================================
12. 패키징/배포 구조 변경점
===============================================================================

12.1. 배포 패키지에 포함되는 애드온

현재 배포 패키지는 payload/mods 아래에 다음 애드온을 포함한다.

   tfm2_meta_item_delegate
   tfm2_meta_champion_tiers
   tfm2_ai_banpick_probe

이 문서의 주 대상은 tfm2_meta_champion_tiers지만,
패키징 구조상 세 애드온이 같이 검증된다.

12.2. manifest 기록

package_manifest.json에는 다음 정보가 들어간다.

   targetGameVersion = 0.4.10
   packageLayoutVersion = 3
   dashboardInstallDir = TFM2.gg
   addons:
      Meta Item Delegate
      Meta Champion Tiers
      AI Banpick Policy

이 manifest는 설치 도구가 설치 상태와 호환성을 판단할 때 사용한다.

12.3. DLL 존재 검증

배포 스크립트는 패키징 중 다음 DLL이 실제로 들어갔는지 검사한다.

   payload\mods\tfm2_meta_item_delegate\tfm2_meta_item_delegate.dll
   payload\mods\tfm2_meta_champion_tiers\tfm2_meta_champion_tiers.dll
   payload\mods\tfm2_ai_banpick_probe\tfm2_ai_banpick_probe.dll

Meta Champion Tiers DLL이 빠진 채 배포되는 문제를 방지한다.

===============================================================================
13. 현재 구현 기준 사용자 안내 문구
===============================================================================

사용자에게 설명할 때는 다음처럼 말하는 것이 가장 정확하다.

13.1. 인게임 메타 티어 애드온

   "대시보드에서 계산한 최신 패치 전세계 대회 기준 메타 티어를
   게임 내부 챔피언 티어 분류표에 S/A/B/C/D/No-Tier로 반영합니다.

   대시보드 OP는 인게임 S, 1티어는 A, 2티어는 B, 3티어는 C,
   4티어는 D, 표본 부족 '-'는 No-Tier로 들어갑니다.

   기존처럼 raw 메타 스코어를 그대로 넣지 않고,
   인게임 표시 체계에 맞춘 앵커값을 사용하기 때문에 C/D로 쏠리는 문제가 줄었습니다."

13.2. 피어리스 룰

   "대시보드에서 피어리스/하드 피어리스 기준으로 보고 있다면,
   인게임 애드온 정책도 해당 룰 기준으로 다시 생성할 수 있습니다.
   단순히 화면만 바꾸는 것과 인게임 정책 TSV를 다시 생성하는 것은 구분됩니다."

13.3. 챔피언 추가 모드

   "설치 도구에서 Steam 창작마당 챔피언 추가 모드를 감지하고,
   모드 단위로 켜고 끌 수 있습니다.
   활성화된 모드의 챔피언은 대시보드 데이터 재생성 시 목록에 포함되며,
   이름/스킬/능력치/스프라이트를 최대한 자동으로 읽어 표시합니다.

   모드 챔피언도 통계가 쌓이면 기존 챔피언과 같은 메타 티어/메타 스코어/꿀챔 점수 산식으로 평가됩니다.
   통계가 아직 없으면 '-' 또는 No-Tier로 남는 것이 정상입니다."

13.4. 적용 시점

   "챔피언 추가 모드 활성/비활성은 게임 재시작 후 적용됩니다.
   대시보드도 최신 통계를 다시 생성해야 새 챔피언 목록과 정책 TSV가 반영됩니다."

14. 검증 포인트
===============================================================================

14.1. 인게임 메타 티어 애드온 검증

확인할 파일:

   Teamfight Manager2\mods\tfm2_meta_champion_tiers\debug.log
   Teamfight Manager2\mods\tfm2_meta_champion_tiers\tier-policy-latest.txt

확인할 내용:

   policy: loaded ... champion tiers
   source=client_post_update ...
   policy_rows=...
   changed=...

tier-policy-latest.txt 안에 챔피언 ID와 S/A/B/C/D/No가 보이면,
애드온이 정책을 읽고 적용한 것이다.

14.2. 정책 기준 검증

확인할 파일:

   champion_tier_policy.tsv

확인할 헤더:

   Scope: tournament
   Region: all
   Role: all
   Model: tfm2gg-meta-v1
   Preset: classic/fearless/hardFearless
   PolicyPresetSource: dashboard setting
   OverallSemantic: dashboard_meta_tier_for_in_game_sabcd_no

확인할 row:

   OP급 챔피언이 S/90.0으로 나오는지
   1티어 챔피언이 A/75.0으로 나오는지
   표본 부족 챔피언이 No로 나오는지

14.3. 챔피언 추가 모드 검증

확인할 파일:

   Teamfight Manager2\config\game\mods.json

확인할 내용:

   enabled_mods에 해당 mod_id가 들어 있는지
   known_workshop_mods에 해당 mod_id가 들어 있는지

확인할 대시보드 payload:

   meta-data.js의 sources.externalChampionMods
   meta-data.js의 sources.externalChampionCount

현재 예시:

   externalChampionCount = 7
   test_mod = 6명
   beast = 1명

확인할 UI:

   대시보드 챔피언 목록에 모드 챔피언이 표시되는지
   이름이 번역 파일 기준으로 나오는지
   아이콘/스프라이트가 공백이 아닌지
   상세 탭에서 스킬 설명이 나오는지

===============================================================================
15. 남아 있는 주의점
===============================================================================

15.1. 게임 재시작 필요

챔피언 추가 모드 활성/비활성은 게임 재시작이 필요하다.
설치 도구가 mods.json을 바꿔도 이미 실행 중인 게임 세션에는 즉시 반영되지 않는다.

15.2. 대시보드 데이터 재생성 필요

챔피언 모드 활성화 후 이미 만들어진 meta-data.js를 계속 보고 있으면,
대시보드에는 새 챔피언이 안 보일 수 있다.

새 챔피언을 보려면 대시보드 통계 재생성/새로고침이 필요하다.

15.3. 통계 없는 챔피언은 No-Tier가 정상

외부 챔피언이 대시보드에 표시되더라도,
아직 세이브/리플레이 통계가 없으면 메타 티어는 '-'가 된다.
인게임 정책에서도 No-Tier로 나가는 것이 정상이다.

15.4. 모드 구조가 표준과 다르면 일부 정보가 비어 보일 수 있음

대시보드는 다음 표준 구조를 기대한다.

   mod.mod_info
   champion\*.data_champion
   text\champion.i18n
   sprite 경로 + #sheet.png
   sprite 경로 + #anim.fanim

모드가 이 구조를 크게 벗어나면 이름, 설명, 이미지, 스킬 일부가 fallback으로 표시되거나 비어 보일 수 있다.

15.5. DLL 포함 창작마당 모드는 주의 필요

설치 도구는 DLL 포함 여부를 표시한다.
DLL 포함 모드는 게임 로직을 바꿀 수 있으므로,
단순 데이터 챔피언 모드보다 호환성 문제가 생길 가능성이 높다.

15.6. style override 포함 모드는 UI 충돌 가능성 있음

mod.override_info에서 champion_view style override가 감지되면 주의 표시를 띄운다.
이런 모드는 게임 내 챔피언 화면을 바꿀 수 있어,
TFM2.gg 애드온이나 다른 모드와 시각적 충돌이 날 수 있다.

===============================================================================
16. 이번 업데이트의 실질적인 의미
===============================================================================

이번 업데이트의 핵심은 "대시보드 분석 결과를 게임 안으로 더 자연스럽게 가져가는 것"이다.

이전에는:

   대시보드에서 메타 티어를 보는 것과
   인게임 티어 분류표가 따로 노는 느낌이 있었다.

현재는:

   대시보드가 최신 패치 전세계 대회 기준으로 메타 티어를 계산하고,
   그 결과를 인게임 S/A/B/C/D/No-Tier 체계에 맞게 변환해 넣는다.

이전에는:

   창작마당 챔피언 추가 모드는 대시보드 분석 범위 밖에 가까웠다.

현재는:

   설치 도구가 챔피언 추가 모드를 감지하고,
   모드 단위로 켜고 끄며,
   활성 모드의 챔피언을 대시보드 목록과 정책 생성 대상에 포함할 수 있다.

즉 TFM2.gg는 이제 기본 챔피언만 보는 도구에서,
"현재 사용자가 실제로 켜 둔 Teamfight Manager 2 모드 환경"을 따라가려는 방향으로 확장되었다.

===============================================================================
17. 짧은 배포용 요약
===============================================================================

이번 업데이트에서는 인게임 메타 티어 동기화와 챔피언 추가 모드 대응을 크게 개선했습니다.

먼저 메타 티어 애드온은 대시보드의 OP/1/2/3/4/- 티어를 게임 내부 S/A/B/C/D/No-Tier로
명확히 변환하도록 수정했습니다. 기존처럼 raw 메타 스코어를 그대로 넣으면 인게임에서 C/D로
쏠릴 수 있었는데, 이제는 티어별 앵커값을 사용해 대시보드 메타 티어와 인게임 티어표가
더 자연스럽게 맞도록 했습니다.

또한 피어리스/하드 피어리스 유저를 위해 대시보드 룰 설정과 인게임 애드온 정책을 동기화할 수
있게 했습니다. 인게임 티어표는 기본적으로 최신 패치 전세계 대회 기준으로 생성되며,
정책 파일 헤더와 적용 로그를 통해 어떤 기준이 적용되었는지 확인할 수 있습니다.

챔피언 추가 모드 대응도 추가되었습니다. 설치 도구에서 Steam 창작마당 챔피언 모드를 감지하고,
모드 단위로 활성/비활성 관리할 수 있습니다. 활성화된 모드의 챔피언은 대시보드 데이터 재생성 시
목록에 포함되며, 이름, 스킬, 능력치, 역할 추정, 스프라이트를 최대한 자동으로 읽어 표시합니다.
통계가 쌓인 모드 챔피언은 기본 챔피언과 같은 메타 티어/메타 스코어/꿀챔 점수 산식으로 평가됩니다.
