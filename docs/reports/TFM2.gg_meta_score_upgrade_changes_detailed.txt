TFM2.gg 대시보드 메타스코어 산식 개선 이후 변경점 상세 보고서
작성일: 2026-06-05
대상: TFM2.gg Meta Dashboard / tfm2gg-meta-v1

===============================================================================
0. 문서 목적
===============================================================================

이 문서는 TFM2.gg 대시보드의 메타스코어 산식이 개선된 뒤 실제로 무엇이 바뀌었는지
매우 자세하게 정리하기 위한 문서이다.

정리 대상은 다음과 같다.

1. 예전 메타 티어 계산 방식
2. 현재 메타 스코어 계산 방식
3. 현재 메타 티어 계산 방식
4. 표본 보정과 자동 표본 기준
5. 픽률/밴률/밴픽률이 산식에 들어가는 방식
6. 클래식/피어리스/하드 피어리스 프리셋 차이
7. 꿀챔 점수의 역할과 산식
8. 인게임 메타 티어 애드온 및 AI 밴픽 애드온과의 연동 기준
9. 개선 이후 얻는 장점과 남아 있는 주의점

핵심 결론부터 말하면, 예전 방식은 "최소 표본을 넘긴 챔피언을 단순 승률 컷으로
나누는 방식"에 가까웠다. 현재 방식은 "표본 불확실성을 보정한 승률 강도,
픽/밴 기반 드래프트 압력, 진행 룰별 가중치, 보수 하한 점수, 백분위 티어 컷"을
함께 사용하는 복합 메타 모델로 바뀌었다.

즉 현재 대시보드의 메타 스코어는 더 이상 단순 승률이 아니다.

===============================================================================
2. 예전 방식 요약
===============================================================================

예전 방식은 매우 단순했다.

기본 흐름은 다음과 같다.

1. 챔피언의 pickCount를 확인한다.
2. pickCount가 5 미만이면 티어를 "-"로 둔다.
3. pickCount가 5 이상이고 winRate가 있으면 승률만으로 티어를 나눈다.

예전 티어 컷은 다음과 같았다.

pickCount < 5 또는 winRate 없음:

   tier = "-"

pickCount >= 5일 때:

   winRate >= 62.0%  -> OP
   winRate >= 57.0%  -> 1
   winRate >= 53.0%  -> 2
   winRate >= 49.0%  -> 3
   그 외            -> 4

이를 의사 코드로 쓰면 다음과 같다.

   if pickCount < 5 or winRate is None:
       return "-"
   if winRate >= 62:
       return "OP"
   if winRate >= 57:
       return "1"
   if winRate >= 53:
       return "2"
   if winRate >= 49:
       return "3"
   return "4"

이 방식의 장점은 이해하기 쉽다는 점이었다.
하지만 단점도 명확했다.

1. 표본 5개와 표본 200개를 거의 같은 방식으로 취급한다.

   예를 들어 5전 4승 1패의 80% 승률과 200전 120승 80패의 60% 승률을 비교하면,
   예전 방식에서는 5전 80%가 지나치게 높게 보일 수 있었다.

2. 픽률과 밴률을 거의 반영하지 못한다.

   하드 피어리스처럼 강한 챔피언이 자주 밴되어 실제 픽률이 낮아지는 환경에서는
   순수 승률만 보면 OP 챔피언을 놓칠 수 있다.

3. 메타가 이미 견제받고 있는지 알 수 없다.

   어떤 챔피언은 승률이 약간 낮아도 밴률이 매우 높을 수 있다.
   이런 챔피언은 "상대가 주기 싫어하는 픽"일 수 있는데, 예전 방식은 이 신호를
   제대로 보지 못했다.

4. 진행 룰 차이를 반영하지 못한다.

   클래식, 피어리스, 하드 피어리스는 밴/픽의 의미가 다르다.
   예전 방식은 모든 룰에서 같은 승률 컷만 사용했다.

5. 역할 필터나 지역 필터처럼 표본이 좁아질 때 너무 흔들린다.

   필터가 좁아질수록 표본이 줄어드는데, 예전 방식은 표본 불확실성에 대한
   별도 보정이 없었다.

6. "메타 스코어"라는 연속 점수가 없었다.

   OP/1/2/3/4라는 등급은 있었지만, 챔피언 간 미세한 차이를 설명할 수 있는
   일관된 0~100 점수는 없었다.

===============================================================================
3. 현재 방식의 큰 구조
===============================================================================

현재 모델 버전은 다음과 같다.

   modelVersion = tfm2gg-meta-v1

현재 방식은 아래 순서로 계산된다.

1. 현재 필터의 통계 범위를 결정한다.

   예:

   - 전체
   - 대회
   - 솔랭
   - 특정 지역
   - 특정 지역 대회
   - 특정 지역 솔랭
   - 1부/2부
   - 특정 역할
   - 특정 패치

2. 현재 표본 기준을 결정한다.

   - 초반 데이터: 최소 5픽
   - 일반 데이터: 최소 10픽
   - 자동: 패치 경과일 또는 경기 수 기준으로 5픽/10픽 자동 선택

3. 현재 범위의 평균 승률과 분산을 이용해 승률 prior를 추정한다.

4. 각 챔피언의 승률을 Bayesian posterior로 보정한다.

5. posterior 평균과 posterior 하한으로 순수 강도 점수를 만든다.

6. 픽률과 밴률을 source별로 보정해 노출도 presence를 만든다.

7. 현재 범위 평균 노출도와 비교해 드래프트 압력 점수를 만든다.

8. 진행 룰 프리셋에 따라 순수 강도와 드래프트 압력을 합쳐 메타 스코어를 만든다.

9. 티어 판정에는 더 보수적인 metaLower를 사용한다.

10. metaLower 순위와 백분위 컷을 함께 적용해 OP/1/2/3/4/-를 결정한다.

11. 별도 지표인 꿀챔 점수는 순수 강도 대비 노출도가 낮거나 높은 정도를 signed score로 계산한다.

===============================================================================
4. 현재 모델 파라미터
===============================================================================

현재 score-model-spec.json의 주요 파라미터는 다음과 같다.

4.1. Posterior 설정

   z = 0.84
   fallbackPriorMean = 0.5
   ratePriorKappa = 20

   kappa 범위:

   early  = [8, 50]
   normal = [12, 80]
   role   = [18, 100]

해석:

- z = 0.84는 posterior 하한을 계산할 때 평균에서 약 0.84 표준편차를 빼는 값이다.
- fallbackPriorMean = 0.5는 현재 범위에서 prior 평균을 추정할 수 없을 때 50%를 기본값으로 쓴다는 뜻이다.
- kappa는 prior의 강도다. 값이 클수록 작은 표본 챔피언의 승률이 평균 쪽으로 더 강하게 당겨진다.
- role 범위의 kappa가 더 높은 이유는 역할 필터가 좁은 표본을 자주 만들기 때문이다.

4.2. Strength 설정

   strength.meanWeight  = 0.7
   strength.lowerWeight = 0.3

순수 강도 점수는 posterior 평균만 보지 않고 posterior 하한도 30% 반영한다.

4.3. Pressure 설정

   pressure.eps   = 0.001
   pressure.scale = 16

드래프트 압력 점수는 평균 노출도 대비 현재 챔피언 노출도가 얼마나 높은지를 로그 비율로 계산한다.
eps는 0 나눗셈과 극단적인 로그 폭주를 막는 안정화 값이다.
scale은 로그 비율을 0~100 점수대에 맞게 확대하는 계수다.

4.4. 프리셋별 메타 스코어 가중치

classic:

   metaStrengthWeight  = 0.84
   metaPressureWeight  = 0.16
   lowerStrengthWeight = 0.88
   lowerPressureWeight = 0.12

fearless:

   metaStrengthWeight  = 0.78
   metaPressureWeight  = 0.22
   lowerStrengthWeight = 0.82
   lowerPressureWeight = 0.18

hardFearless:

   metaStrengthWeight  = 0.72
   metaPressureWeight  = 0.28
   lowerStrengthWeight = 0.78
   lowerPressureWeight = 0.22

해석:

- classic은 승률/강도 중심이다.
- fearless는 밴픽 압력의 의미가 classic보다 커진다.
- hardFearless는 한 번 쓴 좋은 픽을 다시 쓰기 어렵고, OP픽이 밴으로 묶일 가능성이 커지므로
  드래프트 압력 가중치가 가장 높다.

4.5. 티어 컷

현재 티어 컷은 단순 점수 컷이 아니다.
metaLower 하한 조건과 전체 eligible 챔피언 안에서의 백분위 조건을 동시에 본다.

   OP: metaLower >= 56, 상위  8% 이내
   1 : metaLower >= 51, 상위 22% 이내
   2 : metaLower >= 48, 상위 45% 이내
   3 : metaLower >= 44, 상위 70% 이내
   4 : 위 조건을 만족하지 못한 eligible 챔피언
   - : 최소 표본 미달 또는 승률 없음

이 구조 때문에 metaScore가 높아도 무조건 OP가 되지는 않는다.
티어는 metaLower와 순위 백분위를 같이 통과해야 올라간다.

===============================================================================
5. 자동 표본 기준 변경점
===============================================================================

예전 방식은 사실상 "5픽 이상이면 유효"에 가까웠다.

현재는 표본 기준이 다음처럼 바뀌었다.

1. 사용자가 초반 데이터 모드를 선택한 경우

   minSample = 5

2. 사용자가 일반 데이터 모드를 선택한 경우

   minSample = 10

3. 자동 모드인 경우

   우선 replayDateStatus.daysSincePatch를 본다.

   - 마지막 패치 이후 3일 미만이면 초반 데이터로 보고 minSample = 5
   - 마지막 패치 이후 3일 이상이면 일반 데이터로 보고 minSample = 10

4. 날짜 판단이 불가능한 경우

   현재 범위의 경기 수 또는 추정 경기 수를 본다.

   - 경기 수가 100 이상이면 일반 데이터로 보고 minSample = 10
   - 경기 수가 100 미만이면 초반 데이터로 보고 minSample = 5

이 변경의 의미는 다음과 같다.

- 패치 직후에는 데이터가 적으므로 기준을 5픽으로 낮춰 빠르게 흐름을 볼 수 있다.
- 시간이 지나거나 경기 수가 충분하면 기준을 10픽으로 올려 소표본 튐을 줄인다.
- 역할/지역/패치 필터처럼 데이터가 좁아지는 경우에도 현재 범위에 맞춰 유연하게 동작한다.

===============================================================================
6. Bayesian 승률 보정 변경점
===============================================================================

예전 방식은 raw winRate를 그대로 사용했다.

현재 방식은 raw winRate를 바로 믿지 않고 Bayesian posterior로 보정한다.

6.1. prior 평균 추정

현재 범위의 모든 챔피언 통계를 이용해 전체 평균 승률을 구한다.

   priorMean = 전체 wins 합 / 전체 pickCount 합

만약 계산할 데이터가 없으면 fallbackPriorMean = 0.5를 쓴다.

6.2. prior 강도 kappa 추정

현재 범위의 챔피언별 승률 분산을 본다.
관측 분산에서 표본 노이즈를 뺀 between variance를 추정한다.

   observedVar = 챔피언별 승률의 관측 분산
   noiseVar    = 평균 승률 기준의 평균 표본 노이즈
   betweenVar  = max(observedVar - noiseVar, 0.0005)

   kappa = priorMean * (1 - priorMean) / betweenVar - 1

계산된 kappa는 현재 모드별 허용 범위로 clamp된다.

   early  : 8~50
   normal : 12~80
   role   : 18~100

해석:

- 챔피언별 승률 차이가 실제로 많이 벌어져 있으면 kappa가 낮아져 raw 데이터가 더 많이 반영된다.
- 챔피언별 승률 차이가 대부분 표본 노이즈로 보이면 kappa가 높아져 평균 쪽으로 더 많이 당겨진다.

6.3. posterior 계산

각 챔피언에 대해 다음을 계산한다.

   wins   = stat.wins 또는 pickCount * winRate / 100
   trials = pickCount

   alpha = wins + priorMean * kappa
   beta  = losses + (1 - priorMean) * kappa
   total = alpha + beta

   posteriorMean = alpha / total

   posteriorSd = sqrt((alpha * beta) / (total^2 * (total + 1)))

   posteriorLower = clamp(posteriorMean - z * posteriorSd, 0, 1)

여기서 z = 0.84다.

6.4. 개선 효과

예전:

   5전 4승 1패 = 80% 승률
   그대로 OP 후보가 될 수 있음

현재:

   5전 4승 1패라도 prior 평균과 kappa에 의해 평균 쪽으로 당겨짐
   posteriorLower도 낮게 잡히므로 티어 승격이 제한됨

즉 현재 방식은 "소표본 고승률 챔피언이 과도하게 튀는 현상"을 크게 줄인다.

===============================================================================
7. 순수 강도 점수 strengthScore
===============================================================================

현재 모델은 승률 보정 결과로 순수 강도 점수를 만든다.

산식:

   strengthScore = 100 * (
       0.7 * posteriorMean
       + 0.3 * posteriorLower
   )

또 별도로 보수 하한 점수를 둔다.

   strengthLower = 100 * posteriorLower

해석:

- posteriorMean은 "현재 데이터상 평균적으로 어느 정도 강한가"를 나타낸다.
- posteriorLower는 "불확실성을 감안해도 최소한 어느 정도 강하다고 볼 수 있는가"를 나타낸다.
- strengthScore는 평균 판단과 보수 판단을 섞은 점수다.
- strengthLower는 티어 판정에서 더 강하게 쓰이는 보수 기준이다.

이 변경의 핵심은 메타 판단이 raw winRate에서 "보정 승률 기반 순수 강도"로 바뀌었다는 점이다.

===============================================================================
8. 픽률/밴률 기반 노출도 presence
===============================================================================

현재 모델은 픽률과 밴률을 따로 보지 않고, "드래프트에서 얼마나 노출되는가"를 presence로 묶는다.

8.1. 대회 데이터

대회에는 픽과 밴이 모두 있으므로 presence를 다음처럼 계산한다.

   presence = 1 - (1 - pickRate) * (1 - banRate)

이 산식은 "픽되거나 밴될 확률"에 가깝다.

예를 들어:

   pickRate = 30%
   banRate  = 40%

   presence = 1 - (1 - 0.30) * (1 - 0.40)
            = 1 - 0.70 * 0.60
            = 0.58
            = 58%

단순히 pickRate + banRate를 더하면 중복 문제가 생길 수 있으므로,
현재 모델은 보완확률 방식으로 합친다.

8.2. 솔랭 데이터

현재 솔랭 데이터에는 안정적인 밴 데이터가 없다.
그래서 솔랭 source에서는 밴률을 0으로 섞지 않고, pickRate만 presence로 사용한다.

   solo presence = solo pickRate

이 점이 중요하다.
솔랭 밴 데이터가 없다고 해서 banRate = 0으로 넣으면, 대회+솔랭 혼합 통계에서
챔피언의 드래프트 압력이 부당하게 낮아질 수 있다.
현재 모델은 sourceMatchCounts/sourcePickCounts/sourceBanCounts를 사용해 source별로 따로 보정한 뒤
경기 수 가중 평균으로 합친다.

8.3. 역할 필터

역할 필터에서는 역할별 밴 데이터가 원본 구조상 직접 분리되어 있지 않다.
따라서 역할 source에서는 pick 기반 presence를 우선 사용하고, 화면상의 밴률 표시는
별도 개선으로 "전체 밴률"을 표시하도록 바뀌었다.

이 결정은 역할별 통계를 오염시키지 않기 위한 절충이다.

- 역할별 승률/픽률/메타 강도는 역할 통계를 기준으로 본다.
- 밴률은 밴이 역할에 묶여 있지 않으므로 전체 밴률로 표시한다.
- 산식 내부에서는 역할별 밴률이 있는 것처럼 꾸며 넣지 않는다.

===============================================================================
9. source별 노출도 smoothing
===============================================================================

현재 모델은 pickRate/banRate도 그대로 쓰지 않고 beta_rate_mean으로 smoothing한다.

설정:

   ratePriorKappa = 20

source별 baseline을 구한 뒤, 각 챔피언의 픽/밴 카운트를 beta prior로 보정한다.

   pickPost = (pickCount + baselinePick * ratePriorKappa) / (total + ratePriorKappa)
   banPost  = (banCount  + baselineBan  * ratePriorKappa) / (total + ratePriorKappa)

대회 source:

   presence = 1 - (1 - pickPost) * (1 - banPost)

솔랭/역할 source:

   presence = pickPost

여러 source가 섞인 경우:

   presence = source별 presence의 경기 수 가중 평균

이 변경의 효과:

- 특정 source에서 표본이 작을 때 픽률/밴률이 지나치게 0% 또는 100%로 튀는 것을 줄인다.
- 대회+솔랭 혼합 시 밴 데이터가 없는 솔랭을 대회 밴률과 무리하게 섞지 않는다.
- 지역/역할/패치 필터처럼 좁은 통계에서도 노출도 계산이 안정적이다.

===============================================================================
10. 드래프트 압력 점수 draftPressureScore
===============================================================================

현재 모델은 presence 자체를 그대로 메타 스코어에 넣지 않는다.
현재 범위의 평균 presence와 비교해 상대적인 드래프트 압력 점수를 만든다.

산식:

   draftPressureScore = clamp(
       50 + scale * ln((presence + eps) / (baselinePresence + eps)),
       0,
       100
   )

현재 파라미터:

   scale = 16
   eps   = 0.001

해석:

- presence가 현재 범위 평균과 같으면 draftPressureScore는 약 50이다.
- 평균보다 더 자주 픽/밴되면 50보다 높아진다.
- 평균보다 덜 픽/밴되면 50보다 낮아진다.
- 로그를 쓰기 때문에 극단적인 픽률/밴률 차이가 있어도 점수가 무한정 폭주하지 않는다.

예전 방식과의 차이:

- 예전 방식은 밴률 80%인 챔피언과 밴률 5%인 챔피언을 승률이 같으면 거의 같게 봤다.
- 현재 방식은 밴률/픽률이 높아 "상대가 견제하거나 많이 쓰는 챔피언"이면 draftPressureScore가 올라간다.

주의점:

draftPressureScore는 "강함" 자체가 아니다.
이 값은 "메타에서 얼마나 노출되고 견제되는가"에 가까운 신호다.
그래서 현재 모델은 draftPressureScore만으로 티어를 정하지 않고, strengthScore와 섞는다.

===============================================================================
11. 메타 스코어 metaScore
===============================================================================

현재 대시보드의 "메타 스코어"는 다음 산식으로 계산된다.

   metaScore = clamp(
       metaStrengthWeight * strengthScore
       + metaPressureWeight * draftPressureScore,
       0,
       100
   )

여기서 가중치는 사용자가 선택한 진행 룰 프리셋에 따라 달라진다.

11.1. classic

   metaScore = 0.84 * strengthScore + 0.16 * draftPressureScore

해석:

- 승률 기반 순수 강도가 가장 중요하다.
- 픽/밴 압력은 보조 신호로 반영된다.

11.2. fearless

   metaScore = 0.78 * strengthScore + 0.22 * draftPressureScore

해석:

- 피어리스에서는 밴/픽 압력의 의미가 classic보다 커진다.
- 좋은 픽이 반복 사용되지 못하는 구조이므로, 승률 하나만으로 판단하면 덜 정확할 수 있다.

11.3. hardFearless

   metaScore = 0.72 * strengthScore + 0.28 * draftPressureScore

해석:

- 하드 피어리스에서는 강한 챔피언이 풀리기보다 밴으로 묶이는 경우가 더 중요해진다.
- 그래서 draftPressureScore 비중이 가장 높다.

11.4. 중요한 설계 의도

메타 스코어는 "순수하게 좋은 정도"와 "드래프트에서 실제로 견제/노출되는 정도"를 합친 점수다.

따라서 메타 스코어가 높다는 것은 단순히 승률이 높다는 뜻이 아니다.

현재 모델에서 높은 메타 스코어는 보통 다음 중 하나 또는 둘 다를 의미한다.

1. 표본 보정 후에도 승률 강도가 높다.
2. 현재 메타에서 많이 픽되거나 밴된다.

===============================================================================
12. 보수 점수 metaLower
===============================================================================

현재 모델은 표시용 메타 스코어와 티어 판정용 보수 점수를 분리한다.

티어 판정용 점수는 metaLower다.

산식:

   metaLower = clamp(
       lowerStrengthWeight * strengthLower
       + lowerPressureWeight * draftPressureScore,
       0,
       100
   )

프리셋별 산식:

classic:

   metaLower = 0.88 * strengthLower + 0.12 * draftPressureScore

fearless:

   metaLower = 0.82 * strengthLower + 0.18 * draftPressureScore

hardFearless:

   metaLower = 0.78 * strengthLower + 0.22 * draftPressureScore

metaLower의 역할:

- metaScore보다 더 보수적이다.
- posteriorLower를 중심으로 티어 승격을 판단한다.
- "운 좋게 몇 경기 이긴 챔피언"이 높은 티어로 튀는 것을 막는다.
- 티어표의 신뢰도를 올리기 위해 사용된다.

중요한 점:

현재 대시보드에서 표에 보이는 "메타 스코어"는 metaScore다.
하지만 OP/1/2/3/4 티어를 최종 결정하는 주된 기준은 metaLower와 백분위 순위다.

그래서 어떤 챔피언이 metaScore는 높아도 metaLower가 부족하면 OP나 1티어가 되지 않을 수 있다.

===============================================================================
13. 메타 티어 metaTier 결정 방식
===============================================================================

현재 메타 티어는 다음 순서로 결정된다.

1. eligible 여부 확인

   조건:

   - winRate가 있어야 한다.
   - pickCount가 현재 minSample 이상이어야 한다.

   조건을 만족하지 못하면 tier = "-"다.

2. 모든 eligible 챔피언에 대해 metaScore와 metaLower를 계산한다.

3. eligible 챔피언을 다음 우선순위로 정렬한다.

   1순위: metaLower 높은 순
   2순위: metaScore 높은 순
   3순위: winRate 높은 순
   4순위: pickCount 높은 순
   5순위: 챔피언 이름

4. 정렬 순위를 기준으로 percentile을 계산한다.

   percentile = (index + 1) / eligibleCount

5. 티어 컷을 적용한다.

   OP:

      metaLower >= 56
      percentile <= 0.08

   1티어:

      metaLower >= 51
      percentile <= 0.22

   2티어:

      metaLower >= 48
      percentile <= 0.45

   3티어:

      metaLower >= 44
      percentile <= 0.70

   4티어:

      eligible이지만 위 조건을 만족하지 못함

   -:

      미eligible

13.1. 예전 방식과 다른 점

예전:

   승률이 62% 이상이면 OP

현재:

   metaLower가 56 이상이어야 하고,
   전체 eligible 챔피언 중 상위 8% 안에 들어야 OP

예전:

   승률이 57% 이상이면 1티어

현재:

   metaLower가 51 이상이어야 하고,
   전체 eligible 챔피언 중 상위 22% 안에 들어야 1티어

즉 현재 티어는 절대 점수와 상대 순위를 같이 보는 구조다.

13.2. 왜 백분위 컷을 추가했나

고정 점수 컷만 쓰면 특정 세이브에서 티어가 지나치게 많이 생기거나 지나치게 적게 생길 수 있다.

예:

- 전체적으로 승률이 평준화된 세이브
- 특정 패치 초반이라 표본이 부족한 세이브
- 특정 지역/역할만 필터링해서 챔피언 수가 줄어든 화면

이런 경우 백분위 컷이 없으면 티어표가 불안정해진다.

현재 방식은:

- metaLower가 낮으면 순위가 높아도 티어가 제한된다.
- 순위가 낮으면 metaLower가 어느 정도 있어도 상위 티어가 제한된다.

그래서 티어표가 더 보수적이고 안정적으로 나온다.

14. 피어리스/하드 피어리스 대응 변경점
===============================================================================

현재 대시보드에는 진행 룰 프리셋이 있다.

1. classic
2. fearless
3. hardFearless

이 프리셋은 단순 UI 표시가 아니라 실제 산식 가중치를 바꾼다.

14.1. classic

classic은 가장 승률 중심이다.

   strengthScore 비중 84%
   draftPressureScore 비중 16%

권장 사용:

- 일반적인 룰
- 밴 압력이 메타 판단에서 보조 신호인 경우

14.2. fearless

fearless는 밴픽 압력을 더 크게 반영한다.

   strengthScore 비중 78%
   draftPressureScore 비중 22%

권장 사용:

- 피어리스 룰
- 강한 픽이 반복 사용되지 못해 픽률 해석이 classic과 달라지는 경우

14.3. hardFearless

hardFearless는 밴픽 압력을 가장 크게 반영한다.

   strengthScore 비중 72%
   draftPressureScore 비중 28%

권장 사용:

- 하드 피어리스 룰
- OP픽이 실제 픽보다 밴으로 묶이는 경향이 강한 경우

14.4. 애드온 정책 프리셋 동기화

대시보드 화면에서 선택한 룰과 인게임 애드온 정책 룰을 맞출 수 있도록 개선되었다.

정책 프리셋은 다음 우선순위로 결정된다.

1. 환경변수 TFM2_POLICY_PRESET
2. 대시보드 policy-settings 설정
3. 기본값 classic

또한 대시보드에서 "화면 룰을 따라가기" 형태의 설정을 사용할 수 있다.
이 경우 대시보드에서 피어리스/하드 피어리스로 보고 있을 때 애드온 정책 TSV도 같은 룰로
다시 생성할 수 있다.

===============================================================================
15. 꿀챔 점수 추가 및 개선점
===============================================================================

꿀챔 점수는 메타 스코어와 다른 질문에 답하기 위해 추가된 지표다.

메타 스코어:

   "이 챔피언이 현재 메타에서 순수하게 강하고, 실제로 얼마나 견제/노출되는가?"

꿀챔 점수:

   "순수 강도에 비해 아직 덜 픽/밴되고 있는가?"

즉 꿀챔 점수는 메타 티어를 대체하지 않는다.
발굴용 보조 지표다.

15.1. 기존의 문제

초기 꿀챔 점수 설계는 너무 보수적으로 작동해 0.0이 많거나, 값이 매우 낮게 보일 수 있었다.
특히 역할 필터처럼 노출도 범위가 좁은 화면에서는 residualDivisor가 너무 커서 점수가 눌렸다.

이후 개선으로 다음이 반영되었다.

- 현재 필터 안에서 adaptive residual scaling 사용
- 양수뿐 아니라 음수도 허용
- strength 대비 exposure가 높은 챔피언은 과노출 후보로 표시
- strength 대비 exposure가 낮은 챔피언은 저평가 후보로 표시

15.2. 꿀챔 점수의 현재 구조

현재 꿀챔 점수는 eligible 챔피언만 대상으로 계산된다.

eligible 조건:

- 메타 스코어 계산이 가능해야 한다.
- strengthScore가 있어야 한다.
- presence가 있어야 한다.

먼저 현재 필터 안의 eligible 챔피언들로 회귀식을 만든다.

   x = strengthScore
   y = presence

   meanX = strengthScore 평균
   meanY = presence 평균
   slope = max(0, cov(x, y) / var(x))
   intercept = meanY - slope * meanX

각 챔피언의 기대 노출도는 다음과 같다.

   expectedPresence = clamp(
       intercept + slope * strengthScore,
       baselinePresence * 50,
       max(5, maxPresence)
   )

그리고 residual을 계산한다.

   residual = expectedPresence - actualPresence

해석:

- residual > 0이면 강도 대비 실제 노출도가 낮다.
  즉 "저평가/숨은 픽" 후보가 된다.

- residual < 0이면 강도 대비 실제 노출도가 높다.
  즉 "과노출/이미 많이 견제받는 픽" 후보가 된다.

15.3. percentile gap

꿀챔 점수는 residual만 보지 않는다.
현재 필터 안에서의 strength 백분위와 exposure 백분위도 본다.

   rankGap = strengthPercentile - exposurePercentile

해석:

- strengthPercentile이 exposurePercentile보다 높으면, 강도 순위 대비 노출 순위가 낮다는 뜻이다.
- 이 경우 저평가 후보로 본다.
- 반대면 과노출 후보로 본다.

15.4. adaptive residual scaling

residual은 필터 범위에 따라 스케일이 크게 달라진다.

예:

- 전체 대회 통계에서는 presence 차이가 20~50%포인트까지 벌어질 수 있다.
- 역할 필터에서는 presence 차이가 몇 %포인트 수준으로 좁아질 수 있다.

그래서 고정 divisor만 쓰면 역할 필터에서 꿀챔 점수가 너무 낮게 나온다.

현재 설정:

   residualDivisor             = 20
   adaptiveResidualMinDivisor  = 3
   adaptiveResidualQuantile    = 0.75
   adaptiveResidualScale       = 1.25

계산:

   positiveResiduals = abs(residual) 목록
   adaptiveResidual = positiveResiduals의 75% 분위

   adaptiveResidualDivisor = clamp(
       adaptiveResidual * 1.25,
       3,
       20
   )

이렇게 해서 현재 필터 안의 실제 residual 분포에 맞게 점수 스케일을 조절한다.

15.5. 최종 꿀챔 점수 산식

현재 가중치:

   rankGapWeight     = 0.72
   residualGapWeight = 0.28

   totalWeight = rankGapWeight + residualGapWeight

   residualGap = clamp(residual / adaptiveResidualDivisor, -1, 1)

   reliability = sqrt(sample / (sample + minSample * 2))

최종:

   honeyScore = clamp(
       100 * reliability * (
           (rankGapWeight / totalWeight) * rankGap
           + (residualGapWeight / totalWeight) * residualGap
       ),
       -100,
       100
   )

15.6. 꿀챔 점수 해석

양수:

   강도 대비 덜 픽/밴되는 저평가 후보

0 근처:

   강도와 노출도가 대체로 균형

음수:

   강도 대비 이미 많이 픽/밴되는 과노출 후보

주의:

   꿀챔 점수는 "이 챔피언이 좋은가"를 직접 말하지 않는다.
   좋은 정도는 메타 스코어/메타 티어를 봐야 한다.
   꿀챔 점수는 "강도에 비해 아직 덜 알려졌는가"를 보는 보조 지표다.

===============================================================================
16. 메타 스코어와 꿀챔 점수의 관계
===============================================================================

두 지표는 역할이 분리되어 있다.

16.1. 메타 스코어

메타 스코어는 챔피언의 현재 메타 강도를 나타낸다.

반영 요소:

- 보정 승률
- 보수 하한 승률
- 픽률
- 밴률
- source별 노출도
- 진행 룰 프리셋

16.2. 꿀챔 점수

꿀챔 점수는 메타 스코어가 만든 strengthScore를 기반으로 "노출도 대비 저평가 여부"를 본다.

반영 요소:

- strengthScore
- presence
- strength 백분위
- exposure 백분위
- 기대 노출도와 실제 노출도의 차이
- 표본 신뢰도

16.3. 예시 해석

메타 스코어 높음, 꿀챔 점수 높음:

   강한데 아직 덜 픽/밴되는 챔피언.
   실전에서 찾아볼 가치가 큰 후보.

메타 스코어 높음, 꿀챔 점수 낮음 또는 음수:

   강하지만 이미 많이 픽/밴되는 챔피언.
   OP 또는 핵심 메타픽일 수 있으나 숨은 픽은 아니다.

메타 스코어 낮음, 꿀챔 점수 높음:

   강도 자체가 낮으면 조심해야 한다.
   노출도 대비 저평가처럼 보일 수 있지만, 실제 픽 추천으로 보기엔 부족할 수 있다.

메타 스코어 낮음, 꿀챔 점수 낮음:

   현재 모델상 우선순위가 낮은 챔피언.

===============================================================================
17. 밴률과 밴픽률의 의미
===============================================================================

17.1. 밴률

밴률은 해당 챔피언이 밴된 비율이다.

대회 기준:

   banRate = banCount / banOpportunities * 100

챔피언이 실제로 픽되지 않아도 밴률이 높으면,
상대가 해당 챔피언을 주기 싫어한다는 신호로 해석할 수 있다.

17.2. 픽률

픽률은 해당 챔피언이 실제로 선택된 비율이다.

   pickRate = pickCount / pickOpportunities * 100

17.3. 밴픽률

밴픽률은 픽 또는 밴으로 드래프트에 언급된 비율이다.

대회만 볼 때 직관적으로는 다음과 비슷하다.

   banPickRate = (pickCount + banCount) / totalMatch * 100

단, 현재 내부 presence 계산은 단순 합산만 쓰지 않고,
source별 보정과 보완확률 방식도 함께 사용한다.

17.4. 산식 내 역할

메타 스코어에 직접 들어가는 것은 화면에 보이는 banPickRate 그 자체라기보다,
sourceNormalizedPresence()로 보정된 presence다.

대회:

   presence = pick + ban을 보완확률 방식으로 결합

솔랭:

   presence = pick만 사용

혼합:

   source별 presence를 경기 수로 가중 평균

따라서 "밴픽률이 높다"는 것은 대체로 draftPressureScore가 높아질 가능성이 크다는 뜻이지만,
정확한 산식 입력값은 source별 smoothing을 거친 presence다.

19. 인게임 메타 티어 애드온 연동 변경점
===============================================================================

대시보드 산식 개선 이후, 인게임 메타 티어 자동 분류 애드온과의 연동도 정리되었다.

19.1. 기준 범위

메타 티어 자동 분류 정책은 최신 패치 전세계 대회 기준을 사용한다.

현재 정책 생성 흐름:

   champion_tier_policy.tsv:

      scope = tournament
      patch = latest
      region = all
      role = all

즉 인게임 티어표에 들어가는 기준은 "대시보드에서 최신 패치 전세계 대회 통계를 기준으로 계산한
메타 티어"다.

분석용 대시보드는 전체/대회/솔랭/지역/역할을 자유롭게 볼 수 있지만,
게임 내부 티어 자동 분류는 보수적으로 대회 기준만 사용한다.

19.2. 메타 티어와 인게임 티어 매핑

대시보드 메타 티어는 게임 내부 표시 체계에 맞게 다음처럼 변환된다.

   OP -> S
   1  -> A
   2  -> B
   3  -> C
   4  -> D
   -  -> No

19.3. overall 앵커 분리

중요한 개선점은 인게임 티어 정책 TSV의 overall 값이 raw 메타 스코어가 아니라
티어 표시용 앵커값으로 분리되었다는 점이다.

이유:

기존 DLL은 tier 컬럼이 있어도 overall 값이 있으면 overall 숫자를 보고 S/A/B/C/D를 다시 계산할 수 있었다.
그런데 현재 메타 스코어는 보수적으로 압축되어 65를 넘는 경우가 많지 않다.
따라서 raw metaScore를 그대로 overall에 넣으면 인게임에서 대부분 C/D로 보이는 문제가 생길 수 있었다.

현재는 이를 피하기 위해 챔피언 티어 정책에서 다음 앵커값을 사용한다.

   S = 90.0
   A = 75.0
   B = 62.0
   C = 50.0
   D = 35.0
   No = overall 생략

즉 대시보드에서 1티어로 계산된 챔피언은 인게임 정책 TSV에서 A와 75.0으로 나간다.
DLL이 overall을 다시 해석해도 A로 유지되도록 설계한 것이다.

19.4. No 티어 처리

대시보드에서 "-"인 챔피언은 인게임 정책에서 No로 보낸다.
No 티어는 overall을 비워서 native addon이 tier 컬럼을 우선 사용하게 만든다.

이 구조는 저표본/미수집 챔피언을 억지로 C나 D에 넣지 않기 위한 개선이다.

===============================================================================
20. AI 밴픽 애드온 연동 변경점
===============================================================================

AI 밴픽 애드온은 메타 티어 애드온과 목적이 다르다.

메타 티어 애드온:

   인게임 정보/티어표 표시용

AI 밴픽 애드온:

   AI의 밴픽 후보 점수에 메타 기반 bias를 주기 위한 용도

20.1. 기준 범위

AI 밴픽 정책은 최신 패치 overall 기준을 사용한다.

   ai_champion_policy.tsv:

      scope = overall
      patch = latest
      region = all
      role = all

overall은 대회+솔랭 혼합 통계다.

이유:

- AI 밴픽은 인게임 진행에서 다양한 상황에 작동한다.
- 단순 표시용 티어표보다 더 넓은 메타 신호를 반영하는 편이 실전 보정에 유리하다.

20.2. AI용 overall은 별도 스케일

AI 정책의 overall은 티어 표시용 앵커와 다르다.

AI용 기본 앵커:

   S = 80.0
   A = 70.0
   B = 60.0
   C = 50.0
   D = 40.0

여기에 실제 score와 metaLower의 차이를 작게 더한다.

   scoreDelta = clamp((score - 50) / 10, -1, 1) * 2
   lowerDelta = clamp((metaLower - 50) / 10, -1, 1)

   aiOverall = clamp(base + scoreDelta + lowerDelta, 20, 80)

native bias 공식은 정책 헤더에 다음처럼 기록된다.

   clamp((overall - 50) / 20, -1.5, 1.5)

의도:

- AI 밴픽이 너무 과격하게 바뀌지 않게 제한한다.
- 그래도 S/A/B/D 차이는 체감될 수 있게 만든다.
- 표시용 티어와 AI 행동 보정용 점수를 분리한다.

===============================================================================
21. 데이터 범위/지역/역할 관련 변경점
===============================================================================

산식 개선은 단순 계산식만 바꾼 것이 아니라, 계산 대상 범위도 세분화했다.

21.1. 대회/솔랭 분리

현재 대시보드는 대회와 솔랭 통계를 분리해서 볼 수 있고, 전체에서는 둘을 합쳐 볼 수 있다.

대회:

   픽, 밴, 승패, 역할, 경기 날짜 추정, 지역/리그/디비전 분리 가능

솔랭:

   픽, 승패, 날짜, 지역 분리 가능
   단, 안정적인 밴 데이터는 현재 없음

21.2. 지역별 통계

지역별 통계는 대회와 솔랭 양쪽 모두에서 사용할 수 있도록 확장되었다.

지역 예:

   한국
   중국
   유럽
   북미
   남미
   일본

대회 지역은 팀/리그 정보로 추론한다.
솔랭 지역은 solo_rank_matches의 region_id를 사용한다.

21.3. 1부/2부 분리

대회 통계는 지역뿐 아니라 디비전도 분리할 수 있다.

이유:

- 1부와 2부는 선수 능력치, 팀 성향, 챔피언 활용 방식이 다를 수 있다.
- 1부 통계를 2부에 그대로 적용하면 실제 체감과 어긋날 수 있다.

21.4. 역할 필터

역할 필터는 챔피언의 특정 포지션 사용 통계를 기준으로 화면을 좁힌다.

주의:

역할별 밴 데이터는 원본에서 직접 나오지 않으므로, 산식 내부에서 역할별 밴률을 무리하게 만들지 않는다.
대신 화면 표시에서는 전체 밴률을 보여주어 사용자가 밴 압력을 참고할 수 있게 했다.

===============================================================================
22. 리플레이 날짜 추정과 표본 기준 안정화
===============================================================================

현재 모델은 자동 표본 기준을 위해 날짜 정보를 활용한다.

대회 리플레이:

   match_replays 자체에는 날짜가 직접 없으므로,
   match_stats, teams, year_schedules를 조합해 일정 기반 날짜를 추정한다.

솔랭 리플레이:

   SoloRankMatch에 date/result_time이 있으므로 exported 날짜로 사용한다.

날짜 품질은 confidence로 구분된다.

예:

   exported
   high
   medium
   unknown

개선 효과:

- 패치 직후인지 아닌지 더 안정적으로 판단할 수 있다.
- 자동 표본 기준이 단순 경기 수만 보는 것보다 나아진다.
- 리플레이 기록과 최근 추세 분석의 품질도 올라간다.

===============================================================================
23. 외부 챔피언 모드 대응과 산식 영향
===============================================================================

최근 구조에서는 Steam Workshop 챔피언 추가 모드도 감지하고 대시보드에 포함할 수 있도록 확장되었다.

산식 측면의 영향:

1. 외부 챔피언도 champion id/name/icon/model/sprite 정보가 들어오면 대시보드 목록에 표시된다.

2. 통계가 아직 없는 외부 챔피언은 pickCount와 winRate가 없으므로 메타 티어는 "-" 또는 No로 남는다.

3. 외부 챔피언이 실제 세이브/리플레이에 등장해 통계가 쌓이면 같은 tfm2gg-meta-v1 산식으로 평가된다.

4. 인게임 티어 애드온 정책에서도 통계가 없는 챔피언은 No 또는 중립값으로 처리되어,
   데이터 없는 챔피언이 잘못 높은 티어를 받는 것을 막는다.

주의:

외부 챔피언의 모델링/아이콘이 대시보드에 보이려면 모드 리소스 추출과 asset patch가 정상 적용되어야 한다.
통계 산식 자체는 리소스 표시와 별개로 champion id 기준으로 작동한다.

24. 예전 방식 대비 개선 효과
===============================================================================

24.1. 소표본 고승률 튐 감소

예전:

   5전 4승 1패 = 80% 승률
   OP 후보가 될 수 있음

현재:

   prior 보정
   posteriorLower
   minSample 자동 기준
   metaLower 티어 판정
   백분위 컷

이 조합으로 소표본 튐이 크게 줄었다.

24.2. 밴 압력 반영

예전:

   승률만 봄

현재:

   pickRate
   banRate
   source별 presence
   draftPressureScore
   프리셋별 pressure 가중치

특히 피어리스/하드 피어리스에서 밴률 높은 OP픽을 더 잘 잡을 수 있다.

24.3. 진행 룰별 해석 가능

예전:

   classic/fearless/hardFearless 구분 없음

현재:

   룰마다 strength/pressure 가중치가 달라짐
   애드온 정책도 대시보드 룰과 동기화 가능

24.4. 티어표 안정성 증가

예전:

   고정 승률 컷

현재:

   metaLower 절대 조건
   eligible 챔피언 내 백분위 조건
   표본 기준
   posterior 하한

결과적으로 티어표가 더 보수적이고 납득 가능한 형태로 나온다.

24.5. 분석 질문이 분리됨

예전에는 모든 것을 티어 하나로 봐야 했다.

현재는 다음처럼 나뉜다.

   메타 티어   = 현재 티어표상 위치
   메타 스코어 = 강도+드래프트 압력의 연속 점수
   꿀챔 점수   = 강도 대비 저노출/과노출 정도
   승률        = raw 결과
   픽률        = 실제 선택 빈도
   밴률        = 견제 빈도
   밴픽률      = 드래프트 언급 빈도

분석의 해상도가 크게 올라갔다.

24.6. 애드온 연동 신뢰도 상승

예전 문제:

   대시보드에서는 OP/1/2가 보이는데 인게임 티어표에서는 C/D만 보이는 문제가 있었다.

개선:

   메타 티어 정책의 overall을 raw score가 아니라 S/A/B/C/D 앵커로 분리했다.
   No 티어는 overall을 생략한다.
   AI 밴픽 정책은 별도 overall 스케일을 사용한다.

따라서 표시용 정책과 AI 행동 보정용 정책의 의미가 분리되었다.

===============================================================================
25. 현재 산식의 한계와 주의점
===============================================================================

현재 모델은 예전보다 안정적이지만, 완전한 진실 모델은 아니다.
아래 한계는 계속 인지해야 한다.

25.1. 세이브 데이터 품질 의존

메타 스코어는 현재 세이브/리플레이/Meta Exporter 데이터에 의존한다.
데이터가 적거나 export가 실패하면 점수도 제한된다.

25.2. 솔랭 밴 데이터 부재

현재 솔랭은 안정적인 밴 데이터가 없다.
그래서 솔랭 presence는 pickRate 중심으로 계산된다.
향후 솔랭 밴 데이터가 공식/세이브 구조에서 안정적으로 확인되면 별도 도입을 검토할 수 있다.

25.3. 역할별 밴률 직접 분리 불가

원본 밴은 역할에 직접 귀속되지 않는다.
역할 필터에서 전체 밴률을 표시할 수는 있지만, 역할별 밴률이라고 단정하면 안 된다.

25.4. 꿀챔 점수는 추천 점수가 아니다

꿀챔 점수가 높다고 무조건 좋은 픽은 아니다.
반드시 메타 스코어, 메타 티어, 승률, 표본, 역할 적합도를 같이 봐야 한다.

25.5. 패치 초반에는 자동 기준이 완벽하지 않을 수 있다

날짜 추정이 unknown이거나 리플레이가 적으면 자동 표본 기준은 경기 수 기반 fallback을 사용한다.
이 경우 사용자가 초반/일반 표본 모드를 직접 바꾸는 것이 더 명확할 수 있다.

25.6. 외부 챔피언 모드의 리소스/통계 분리

외부 챔피언은 리소스가 들어와도 통계가 없으면 No 또는 "-"로 남는다.
반대로 통계가 있어도 리소스 추출이 실패하면 대시보드에서 이미지가 비어 보일 수 있다.

26. 변경 전후를 한눈에 보는 요약표
===============================================================================

항목: 티어 기준

   예전:
      raw winRate 고정 컷

   현재:
      posterior 보정 승률 + 드래프트 압력 + metaLower + 백분위 컷

항목: 최소 표본

   예전:
      5픽 고정에 가까움

   현재:
      초반 5픽 / 일반 10픽 / 자동 판단

항목: 승률 처리

   예전:
      raw winRate 직접 사용

   현재:
      Bayesian posteriorMean/posteriorLower 사용

항목: 픽률 처리

   예전:
      티어 산식에 실질 반영 약함

   현재:
      source별 smoothing 후 presence에 반영

항목: 밴률 처리

   예전:
      티어 산식에 실질 반영 약함

   현재:
      대회 source의 presence와 draftPressureScore에 반영

항목: 피어리스 대응

   예전:
      없음

   현재:
      classic/fearless/hardFearless별 pressure 가중치 차등 적용

항목: 티어 안정성

   예전:
      고정 승률 컷이라 세이브별 편차 큼

   현재:
      절대 하한 조건 + 상대 백분위 조건으로 안정화

항목: 꿀챔 발굴

   예전:
      없음

   현재:
      strength 대비 exposure 차이를 signed score로 계산

항목: 인게임 티어 애드온

   예전:
      raw score를 overall에 넣으면 C/D로 쏠릴 수 있음

   현재:
      OP/1/2/3/4/-를 S/A/B/C/D/No 앵커로 변환

항목: AI 밴픽 애드온

   예전:
      표시용 티어와 AI bias 의미가 섞일 수 있음

   현재:
      AI용 overall 스케일을 별도 사용

===============================================================================
27. 실제 사용자 관점에서 좋아진 부분
===============================================================================

27.1. "승률만 높은 함정픽"을 덜 믿게 된다.

표본이 적은 챔피언은 posterior와 metaLower가 낮게 잡히므로, 단순 승률만 보고 높은 티어를 받기 어렵다.

27.2. "밴 때문에 픽률이 낮은 OP픽"을 더 잘 잡는다.

특히 하드 피어리스에서 밴률 높은 챔피언이 draftPressureScore를 통해 더 잘 반영된다.

27.3. "좋은데 덜 알려진 픽"을 따로 찾을 수 있다.

꿀챔 점수가 메타 티어와 분리되어 있어서, 이미 유명한 OP픽과 숨은 픽을 구분할 수 있다.

27.4. 필터를 바꿔도 해석이 더 안정적이다.

지역/역할/패치/대회/솔랭 필터가 바뀌면 현재 범위 안에서 prior와 baseline을 다시 잡는다.
따라서 모든 화면에 같은 절대 기준을 억지로 적용하지 않는다.

27.5. 인게임 애드온과 대시보드 표시가 더 잘 맞는다.

대시보드 메타 티어를 S/A/B/C/D/No로 명확히 변환해 인게임 티어표에 넣으므로,
예전처럼 대시보드에서는 OP/1티어인데 인게임에서는 C/D만 보이는 문제가 줄어든다.

27.6. 룰 프리셋이 실질적으로 의미를 가진다.

클래식/피어리스/하드 피어리스 선택이 단순 표시가 아니라 실제 메타 스코어와 애드온 정책에 영향을 준다.

===============================================================================
28. 결론
===============================================================================

이번 메타스코어 산식 개선의 본질은 다음 한 문장으로 정리할 수 있다.

   "승률 컷 기반 티어표를, 표본 불확실성과 드래프트 압력까지 반영하는 메타 추정 모델로 바꾼 것"

예전 방식은 빠르고 직관적이었지만, 표본 수, 밴 압력, 피어리스 룰, 지역/역할 필터,
솔랭/대회 차이를 충분히 설명하지 못했다.

현재 tfm2gg-meta-v1 방식은 다음을 함께 본다.

- raw 승률
- wins/losses
- pickCount
- 현재 범위 평균 승률
- posteriorMean
- posteriorLower
- pickRate
- banRate
- source별 presence
- baselinePresence
- draftPressureScore
- 진행 룰별 strength/pressure 가중치
- metaScore
- metaLower
- eligible 챔피언 내 백분위 순위
- 꿀챔 점수용 strength-exposure gap

그 결과 대시보드는 단순 티어표를 넘어, 현재 세이브/패치/지역/룰에서 어떤 챔피언이
진짜로 강한지, 누가 이미 견제받고 있는지, 누가 아직 덜 노출되어 있는지를 더 정교하게 보여준다.

남은 개선 방향은 다음과 같다.

1. 솔랭 밴 데이터가 안정적으로 확인될 경우 source별 ban presence에 포함
2. 더 많은 세이브 샘플로 티어 컷과 pressure scale 검증
3. 외부 챔피언 모드의 통계/리소스 추출 안정성 추가 강화
4. 꿀챔 점수의 사용자 해석 문구와 예시 강화
5. 애드온 debug log를 GUI에서 더 직접적으로 보여주는 기능 강화

현재 기준으로는 기존 승률 컷 방식보다 신뢰도, 설명력, 룰 대응력, 인게임 연동 일관성이 모두 좋아졌다.
